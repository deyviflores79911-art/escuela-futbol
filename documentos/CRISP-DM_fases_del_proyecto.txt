#####################################################################
  QUE ES CRISP-DM
#####################################################################

CRISP-DM significa "Cross Industry Standard Process for Data Mining"
(proceso estandar para la mineria de datos, valido para cualquier
industria). Se publico en el ano 2000 y es la metodologia mas usada
para proyectos de Data Mining.

No dice QUE algoritmo usar: dice EN QUE ORDEN trabajar y QUE preguntas
responder en cada paso, para que el proyecto resuelva un problema real
y no solo produzca graficos.

Tiene 6 fases. No es una linea recta: es un CICLO. Se puede volver a
una fase anterior cuando se aprende algo nuevo (por ejemplo, al evaluar
un modelo se descubre que faltan datos y se vuelve a preparar).

         +-----------------------------+
         | 1. Comprension del negocio  |<------------------+
         +-----------------------------+                   |
                ^          |                               |
                |          v                               |
         +-----------------------------+                   |
         | 2. Comprension de los datos |                   |
         +-----------------------------+                   |
                           |                               |
                           v                               |
         +-----------------------------+                   |
         | 3. Preparacion de los datos |<------+           |
         +-----------------------------+       |           |
                           |                   |           |
                           v                   |           |
         +-----------------------------+       |           |
         | 4. Modelado                 |-------+           |
         +-----------------------------+                   |
                           |                               |
                           v                               |

         +-----------------------------+

#####################################################################
  FASE 1 - COMPRENSION DEL NEGOCIO
#####################################################################

a) QUE ES
   Entender el problema de la organizacion ANTES de tocar los datos.
   Se define que se quiere lograr, como se va a medir el exito y que
   recursos y restricciones hay. Es la fase mas importante: un modelo
   perfecto que responde la pregunta equivocada no sirve.

b) TAREAS DE CRISP-DM
   - Determinar los objetivos del negocio.
   - Evaluar la situacion (recursos, restricciones, riesgos).
   - Definir los objetivos de Data Mining (traducir el problema a una
     tarea tecnica).
   - Hacer el plan del proyecto.

c) EN ESTE PROYECTO (mineria_pagos.py, linea 131)
   Problema del negocio:
     La escuela de futbol cobra mensualidades y muchas llegan tarde.
     Hoy solo se entera cuando el pago ya se atraso.

   Objetivo del negocio:
     Saber ANTES del vencimiento que alumnos tienen riesgo de pagar
     tarde, para recordarle al tutor a tiempo (por WhatsApp).

   Objetivo de Data Mining (la traduccion tecnica):
     - CLASIFICACION: predecir si un pago llegara "a tiempo" (0) o
       "atrasado" (1).
     - AGRUPAMIENTO (clustering): separar a los alumnos en grupos segun
       su comportamiento de pago (puntuales, ocasionales, morosos).

   Criterio de exito:
     El modelo debe detectar los atrasos MEJOR que adivinar. Como la
     mayoria de los pagos llega a tiempo, "adivinar siempre a tiempo"
     ya acierta mucho; por eso no basta mirar la exactitud: importa
     cuantos atrasos detecta (sensibilidad) y el AUC (0,5 = azar).

   Situacion y restricciones:
     - Los datos estan en el Data Warehouse DW_EscuelasDeportivas,
       tabla de hechos H_PAGOS, que carga el paquete SSIS.
     - Los datos NO son de una escuela real: 300 pagos son los de
       ejemplo de la base entregada (REC-) y 562 son simulados (SIM- y
       PRB-) para tener mas casos. Lo real es el proceso.
     - La herramienta: Python (pandas, scikit-learn, matplotlib,
       seaborn), porque se conecta directo al SQL Server y se puede
       automatizar al final del SSIS.

d) SE ENTREGA
   La pregunta clara ("que alumnos pagaran tarde?"), el tipo de tarea
   (clasificacion + clustering) y como se medira el exito.

#####################################################################
  FASE 3 - PREPARACION DE LOS DATOS
#####################################################################

a) QUE ES
   Dejar los datos listos para el modelo: elegir que filas y columnas
   usar, limpiarlos, crear variables nuevas, transformarlas y resolver
   problemas como el desbalance de clases. Suele ser la fase que mas
   tiempo lleva.

b) TAREAS DE CRISP-DM
   - Seleccionar los datos.
   - Limpiar los datos.
   - Construir datos (variables nuevas).
   - Integrar datos de varias fuentes.
   - Dar formato a los datos.

c) EN ESTE PROYECTO (mineria_pagos.py, linea 313)
   Seleccion - que NO se usa y por que (decision clave):
     monto_pagado, saldo_pendiente, dias_atraso y estado del pago se
     conocen DESPUES de pagar. Usarlos seria "hacer trampa": el modelo
     veria la respuesta. Esto se llama fuga de datos (data leakage).

   Seleccion - que SI se usa (se conoce ANTES del vencimiento):
     - categoria (texto)
     - metodo de pago (texto)
     - monto de la mensualidad (numero)
     - % de atrasos previos (numero, variable nueva)

   Construccion - variable nueva "% de atrasos previos":
     Para cada pago, que porcentaje de los pagos ANTERIORES de ese
     mismo alumno llego tarde. Es su historial, lo mismo que miraria
     cualquier cobrador. Se calcula ordenando los pagos por alumno y
     fecha y contando solo los anteriores (nunca el actual).

   Limpieza:
     El primer pago de cada alumno no tiene historial, asi que se deja
     fuera del modelo. Quedan 755 filas para entrenar (de 862).

   Formato (transformacion):
     - Las columnas de texto se convierten en columnas 0/1 (one-hot
       encoding): por ejemplo "Metodo = Efectivo" vale 1 o 0.
     - Para la regresion logistica los numeros se llevan a la misma
       escala (StandardScaler).

   Matriz preparada (la tabla que entra al modelo):
     755 filas y 12 columnas: 5 de categoria (0/1), 4 de metodo de
     pago (0/1), el monto, el % de atrasos previos y "Atrasado" (lo que
     se predice). La app muestra las primeras 8 filas (pantalla
     Analisis, seccion 2). Linea 957 de mineria_pagos.py.

   Desbalance de clases:
     En las 755 filas hay 492 pagos a tiempo y 263 atrasados: 1,9 a 1.
     Con tanta diferencia el modelo tiende a decir siempre "a tiempo".
     Se prueba una correccion: class_weight='balanced' (le da mas peso
     a los atrasos al aprender). Graficos 6 y 7.

   Integracion:
     La hizo el SSIS antes de Python: unio la base transaccional en el
     Data Warehouse (hechos + dimensiones).

d) SE ENTREGA
   La tabla final para el modelo: 755 filas, 4 variables de entrada y
   la variable a predecir (atrasado 0/1).

  FASE 4 - MODELADO
#####################################################################

a) QUE ES
   Elegir las tecnicas, entrenar los modelos y ajustar sus parametros.
   Se prueban varios modelos con el MISMO metodo de prueba, para
   compararlos de forma justa.

b) TAREAS DE CRISP-DM
   - Seleccionar la tecnica de modelado.
   - Disenar la prueba (como se va a evaluar).
   - Construir el modelo.
   - Evaluar el modelo (desde lo tecnico).

c) EN ESTE PROYECTO (mineria_pagos.py, linea 359)
   Tecnicas (clasificacion):
     1. Arbol de decision (profundidad maxima 3: facil de explicar).
     2. Random Forest (300 arboles).
     3. Regresion logistica.
   Cada uno se prueba SIN y CON balanceo de clases: 6 combinaciones.

   Diseno de la prueba:
     Validacion cruzada de 5 partes, SEPARANDO POR ALUMNO
     (StratifiedGroupKFold): todos los pagos de un alumno quedan del
     mismo lado. Asi el modelo siempre se evalua con alumnos que no vio
     al aprender (si no, "memorizaria" a los alumnos).
     Semilla fija = 42: el mismo dato da siempre el mismo resultado.

   Resultados de la validacion cruzada (promedio de las 5 partes):

     Modelo               Balanceo  Exactitud Precision Sensib.  F1    AUC
     -------------------  --------  --------- --------- ------- ----- -----
     Arbol de decision    no        65,8 %    52,7 %    35,3 %  0,40  0,65
     Random Forest        no        68,9 %    60,2 %    33,2 %  0,42  0,68
     Regresion logistica  no        69,5 %    59,8 %    39,1 %  0,47  0,70
     Arbol de decision    si        62,8 %    47,3 %    60,1 %  0,52  0,67
     Random Forest        si        63,3 %    48,1 %    59,3 %  0,53  0,68
     Regresion logistica  si        66,9 %    52,1 %    62,3 %  0,57  0,70

   Eleccion del mejor:
     Se elige por F1 (equilibrio entre detectar atrasos y no dar falsas
     alarmas): REGRESION LOGISTICA CON BALANCEO (F1 0,57; AUC 0,70).

   Lo que muestra la tabla:
     El balanceo casi DUPLICA los atrasos detectados (sensibilidad de
     ~36 % a ~61 %), a cambio de algunas falsas alarmas mas (la
     precision baja de ~58 % a ~49 %). Para la escuela conviene: es
     mejor recordarle a un tutor que iba a pagar que no avisarle al que
     se iba a atrasar.

   Tecnica de agrupamiento (clustering), en la fase 6:
     K-Means con 2 rasgos de cada alumno: % de pagos atrasados y dias
     de atraso promedio.

d) SE ENTREGA
   Los modelos entrenados y la tabla de comparacion (grafico 8).

  PREGUNTAS QUE PODRIA HACER LA INGENIERA
#####################################################################

P: Por que no usaste dias_atraso o saldo_pendiente para predecir?
R: Porque se conocen despues de pagar. Si los uso, el modelo "ve la
   respuesta" (fuga de datos) y da numeros falsamente buenos.

P: Por que separar la validacion por alumno?
R: Porque los pagos de un mismo alumno se parecen. Si un alumno
   aparece al entrenar y al probar, el modelo lo reconoce en vez de
   aprender un patron. Separando por alumno, siempre se prueba con
   alumnos nuevos.

P: Por que elegiste por F1 y no por exactitud?
R: Porque 65 % de los pagos llegan a tiempo: diciendo siempre "a
   tiempo" ya se acierta 65 %, pero no se detecta ningun atraso. El F1
   premia detectar atrasos sin llenar de falsas alarmas.

P: Que hace el balanceo de clases?
R: Le da mas peso a los atrasos al aprender, porque son menos (1,9 a
   tiempo por cada atrasado). Sube los atrasos detectados de ~36 % a
   ~61 %.

P: Por que 3 grupos en K-Means si la silueta dice 6?
R: Porque 3 grupos (puntuales, ocasionales, morosos) se pueden usar en
   la escuela; 6 grupos serian dificiles de explicar y de accionar. La
   silueta se muestra para que la decision sea transparente.

P: El modelo es bueno?
R: Es modesto (AUC 0,74). Supera al azar y detecta 2 de cada 3
   atrasos, asi que sirve para priorizar recordatorios. Los datos son
   de ejemplo y simulados: con datos reales habria que repetirlo.

P: Para que sirve el PCA si ya tenias K-Means?
R: K-Means forma los grupos con 2 rasgos. PCA toma las 9 variables del
   alumno y las resume en 2 ejes para poder DIBUJARLAS. Si los colores
   de K-Means se ven separados en el grafico del PCA, los grupos son
   distintos de verdad, no solo en esos 2 rasgos. Los 2 ejes guardan el
   54 % de la informacion: el resto se pierde al resumir.

P: Por que cambiaron los numeros por categoria desde el 14/10?
R: Porque se encontro y corrigio un error de datos: 45 alumnos estaban
   en una categoria que no era de su edad. Al pasarlos a su categoria,
   sus pagos cuentan en la categoria correcta. Es un ejemplo de volver
   a la fase 2 (calidad de datos) dentro del ciclo de CRISP-DM.

P: Donde esta cada fase en el codigo?
R: En mineria_pagos.py, en orden: linea 131 (negocio), 143 (datos),
   313 (preparacion), 359 (modelado), 462 (evaluacion) y 594
   (despliegue). Las salidas para la app estan al final: 808 (riesgo),
   861 (datos de graficos) y 901 (patrones).

P: Como se repite el ciclo?
R: Ejecutando el paquete SSIS: carga el Data Warehouse y su ultima
   tarea vuelve a correr las 6 fases. El dashboard, el Word y las
   pantallas de la app muestran la hora real del nuevo analisis.
