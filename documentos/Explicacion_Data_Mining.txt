3. COMPROBACION DIRECTA EN SQL, SIN PYTHON
---------------------------------------------------------------------
Atrasado = fecha_pago posterior a fecha_vencimiento (misma regla del SSIS).
Total:

    USE Sistema_EscuelasDeportivas;
    SELECT COUNT(*) AS pagos,
           SUM(CASE WHEN P.fecha_pago > M.fecha_vencimiento
                    THEN 1 ELSE 0 END) AS atrasados
    FROM PAGO P
    JOIN MENSUALIDAD M ON M.id_mensualidad = P.id_mensualidad;

Por metodo: agregar JOIN METODO_PAGO y GROUP BY MP.nombre.
Por categoria: agregar JOIN a INSCRIPCION, GRUPO y CATEGORIA y
GROUP BY C.nombre.

Resultado de la comparacion:

6. QUE ES REAL Y QUE NO
---------------------------------------------------------------------
La base hoy tiene:
  - 300 pagos REC-: datos de ejemplo de la base entregada, sin modificar.
    (El cambio de fechas y metodos que se habia hecho antes se deshizo
    el 05/10.)
  - 502 pagos SIM-: SIMULADOS, agregados con generar_pagos_prueba.py,
    con patrones programados a proposito.
  - 60 pagos PRB-: SIMULADOS, agregados con pagos_prueba_60.sql (familias
    morosas que pagan en efectivo, para ver que el dashboard reacciona).
  Total: 862 pagos; 562 simulados (SIM- y PRB-). El dashboard y el Word
  los cuentan asi desde el 12/10.

ES REAL:
  - La conexion a SQL Server y la lectura de H_PAGOS.
  - Los calculos (coinciden con SQL, punto 3).
  - El entrenamiento y la evaluacion del modelo.
  - Que se puede repetir con el mismo resultado (semilla 42).

NO ES REAL:
  - El comportamiento de los tutores: ningun pago es de una escuela
    verdadera.
  - Los patrones de los pagos SIM- y PRB- (efectivo mas atrasado, familias
    morosas) fueron programados, asi que el modelo "descubre" lo que se
    puso en los datos.
  - Los 300 REC- tampoco son reales: son datos de ejemplo con un patron
    repetitivo.

Frase para decir: "Lo real es el proceso: lee el Data Warehouse,
calcula, entrena y evalua. Los datos son de ejemplo y simulados, asi
que los resultados no describen una escuela real."

* EL MODELO ES MODESTO: AUC 0,70 en validacion cruzada (0,74 con los
  alumnos nuevos). Su exactitud (67 %) apenas supera la de adivinar

* EL PCA PIERDE INFORMACION: resume 9 variables en 2 ejes que guardan

---------------------------------------------------------------------
LA IDEA
---------------------------------------------------------------------
No se trataba de hacer un grafico bonito, sino de agregar la etapa de
Data Mining a un proyecto que ya existia: base transaccional -> SSIS ->
Data Warehouse. Necesitabamos una herramienta que leyera directo de ese
Data Warehouse, hiciera todo el analisis en un proceso que se pueda
repetir y se pudiera conectar al final del ETL. Ademas, la ingeniera
pidio explicitamente Python.


---------------------------------------------------------------------
COMPARACION HONESTA
---------------------------------------------------------------------
ORANGE
  Bien:  Gratis, muy visual, se aprende rapido y es excelente para
         exponer: se ven los bloques y el flujo. Por dentro usa Python y
         scikit-learn. Tambien puede leer de SQL Server con su bloque
         "SQL Table".
  Aqui:  Esta pensado para trabajar abriendo su ventana, no para correr
         solo al final de un paquete SSIS. Los graficos se personalizan
         menos.

R
  Bien:  Gratis, muy fuerte en estadistica, se conecta a SQL Server y
         tambien se puede automatizar.
  Aqui:  Tecnicamente tambien servia. Se eligio Python porque es mas
         usado en la industria y lo pidio la ingeniera.

WEKA
  Bien:  Gratis, clasico en universidades, muchos algoritmos listos.
  Aqui:  Interfaz antigua, graficos basicos, mas dificil de integrar con
         nuestro flujo.

RAPIDMINER (hoy Altair AI Studio)
  Bien:  Visual y potente, con flujos profesionales.
  Aqui:  Es comercial: sus licencias gratuitas o educativas tienen
         condiciones.

POWER BI
  Bien:  Excelente para dashboards y se conecta a SQL Server.
  Aqui:  No esta hecho para entrenar y evaluar modelos (validacion
         cruzada, curva ROC, balanceo de clases).

SSAS DATA MINING
  Bien:  Venia integrado con SQL Server.
  Aqui:  Segun la documentacion de Microsoft, fue declarado obsoleto en
         SQL Server 2017 y retirado desde SQL Server 2022; el servidor
         del proyecto es 2025.


---------------------------------------------------------------------
POR QUE PYTHON ENCAJA CON ESTE PROYECTO (comprobado en el equipo)
---------------------------------------------------------------------
- Se conecta directo al SQL Server con pyodbc y lee H_PAGOS con una
  consulta SQL normal.
- Se automatiza: el script ya esta agregado al final del SSIS como
  ACTUALIZAR_DASHBOARD, y ya se comprobo dentro de Visual Studio (el SSIS
  lo ejecuto el 05/10/2026 a las 00:37).
- Es reproducible: con la semilla 42, el mismo dato da el mismo
  resultado, y cualquiera puede leer cada paso en el codigo.
- Es gratuito: Python, pandas, scikit-learn, matplotlib y seaborn son de
  codigo abierto.
- Es estandar en la industria: es de lo mas usado para Data Science.


---------------------------------------------------------------------
QUE GANO EL PROYECTO
---------------------------------------------------------------------
- Un solo comando genera 13 graficos, el dashboard y el Word, siempre
  coherentes entre si.
- Las conclusiones se escriben solas con los numeros reales: si cambian
  los datos, cambian las frases (punto 4 de la Parte A).
- Validacion mas rigurosa: separar los alumnos del examen, comparar 3
  modelos y probar el balanceo. En Orange tambien se puede, pero aqui
  todo queda escrito y se puede revisar.
- Se puede auditar: cada numero tiene una linea de codigo detras y se
  puede comprobar en SQL (punto 3 de la Parte A).


---------------------------------------------------------------------
LIMITACIONES (para no quedar mal si preguntan)
---------------------------------------------------------------------
- Requiere programar. Orange se explica mas facil arrastrando bloques
  frente a la clase.
- Es menos visual mientras se trabaja: el flujo esta en el codigo, no en
  un diagrama.
- Depende del equipo: las librerias estan instaladas para el usuario de
  Windows; si el SSIS corriera en otro servidor habria que instalarlas
  alli.
- Mas control significa mas decisiones propias (semilla, profundidad del
  arbol, K = 3), y hay que saber explicarlas.
